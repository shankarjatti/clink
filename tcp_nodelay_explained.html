01 / The Latency Trap

Why Default TCP Stalls RF Signals

⚠️ Nagle's Algorithm (RFC 896 — 1984)

Designed originally for slow ARPANET/dial-up connections to avoid sending tiny 1-byte Telnet keystrokes wrapped in 40-byte TCP/IP headers (the "small packet problem").

The Rule: If there is any unacknowledged data in flight, TCP refuses to transmit new packets until either:

  • A full MSS (Maximum Segment Size ≈ 1460B) buffer fills up, OR
  • An ACK packet arrives back from the receiver.
🛑 The "Deadly Synergy" with Delayed ACKs

RFC 1122 introduced Delayed ACKs: the receiving OS delays sending an acknowledgment for up to 40ms – 200ms, hoping to piggyback the ACK on return data.

The Deadlock: The sender is waiting for an ACK before transmitting next frame. The receiver is waiting 100ms before sending an ACK. Result: Continuous 40-200ms micro-freezes, causing USRP ring buffers to overflow and GUI waveforms to stutter.

03 / Code Implementation

How We Configured Sockets in This Repo

In src/net_protocol.h, we encapsulate the setsockopt syscall to disable Nagle's algorithm and expand kernel socket buffers:

// Disables Nagle's algorithm to force immediate kernel packet dispatch inline bool set_tcp_nodelay(int fd) { int flag = 1; return setsockopt(fd, IPPROTO_TCP, TCP_NODELAY, reinterpret_cast<char*>(&flag), sizeof(flag)) == 0; } // Expands OS send and receive buffers to 4 MB to prevent kernel drops under 8 MB/s load inline bool set_socket_buffers(int fd, int buffer_size_bytes = 4 * 1024 * 1024) { int snd = buffer_size_bytes; int rcv = buffer_size_bytes; bool ok1 = (setsockopt(fd, SOL_SOCKET, SO_SNDBUF, reinterpret_cast<char*>(&snd), sizeof(snd)) == 0); bool ok2 = (setsockopt(fd, SOL_SOCKET, SO_RCVBUF, reinterpret_cast<char*>(&rcv), sizeof(rcv)) == 0); return ok1 && ok2; }
📤 Where Senders Use It (S1 & S2)

Inside src/net_streamer.cpp, immediately upon calling connect(), both set_tcp_nodelay(sock_fd_) and set_socket_buffers(sock_fd_) are executed before transmitting the first byte.

📥 Where Receivers Use It (S2 & S3)

Inside src/net_streamer.cpp, immediately after accept() returns a new client file descriptor, the listening worker applies set_tcp_nodelay(client_fd) so all incoming acknowledgments and flow controls are instantaneous.
